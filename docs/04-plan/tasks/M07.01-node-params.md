## Description

Nodes can be configured with `llm:` and `tools:`, but reusable node types also need
domain parameters that are neither state nor model settings (thresholds, prompts,
table names). Today that forces closure factories outside YAML.

Proposed: `params: {…}` on a node, delivered through an opt-in `params` keyword —
the same convention as `llm`. Optionally `@registry.node("x", params_model=Model)`
validates at build time.

## Acceptance Criteria

- [ ] `params:` (mapping) on `NodeConfig`; rejected on subgraph nodes
- [ ] Functions accepting a `params` keyword receive it; `params:` on a non-opting function raises (as with `llm`)
- [ ] With `params_model`, params are validated at build time and the node gets the model instance
- [ ] Works together with `llm` injection
- [ ] Runnable example + README YAML reference + regenerated JSON Schema
