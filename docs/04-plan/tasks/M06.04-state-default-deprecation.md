## Description

`state:` fields accept `default:`, but `build_state_class()` only stores it on
`__field_defaults__`; LangGraph never applies it. Reproduced: a node reading a field
declared with `default: 5` sees it missing. Users reasonably expect initialization.

Decision (session 013): option A — keep the key (removing it would break YAML), emit
a `DeprecationWarning` when it is set, and document it as introspection-only.
Implementing real defaults (option B: Pydantic state model) is deferred because it
changes what nodes receive (model instead of dict). See ADR-010.

## Acceptance Criteria

- [ ] Setting `default:` emits a `DeprecationWarning` that says LangGraph does not apply it
- [ ] README YAML reference and the `declared_state` example describe `default:` as introspection-only
- [ ] `__field_defaults__` is still populated (no behaviour change for introspection users)
- [ ] Test asserts the warning
