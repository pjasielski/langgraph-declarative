## Description

Prove the *capability*, not the wiring. A unit test asserting that `compile()`
received a checkpointer proves plumbing; it does not prove a graph can pause and
resume. Build a real two-tool HITL graph in YAML — one read-only tool, one write
tool where the write is gated behind an approval node — and assert observable
behaviour.

The critical rule: **assert the side effect, not the return status.** A graph that
returns cleanly while having written nothing, or having written despite a rejection,
passes a status-code test and fails the only thing that matters.

## Acceptance Criteria

- [ ] New `tests/test_hitl.py` with a YAML fixture in `tests/fixtures/`
- [ ] Graph shape mirrors the reference: `agent`, `tools`, `approval`, `execute`
- [ ] Read-only tool path runs to completion **without** pausing
- [ ] Write path **pauses**: `__interrupt__` present in the returned state
- [ ] Resume with accept → the side effect **happens** (assert the mutated file/dict/counter)
- [ ] Resume with reject → the side effect **does not happen** (assert target unchanged)
- [ ] State survives across turns on the same `thread_id`; a different `thread_id` is isolated
- [ ] A graph built **without** a checkpointer still behaves exactly as before (regression guard)
- [ ] Test uses `InMemorySaver` supplied *by the test*, never a library default
